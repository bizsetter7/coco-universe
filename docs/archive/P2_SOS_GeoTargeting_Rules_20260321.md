## PART 1. GeoTargeting 시스템 규칙

### 1-1. 기존 설계 원본 (P2_GeoTargeting_System_Rules)

```
우선순위 정렬 기준:
1순위: Grand/Premium (지역 무관 최상단)
2순위: 내 지역 나머지 등급 (거리 순)
3순위: 타지역 Grand/Premium
4순위: 타지역 나머지

거리 계산: Haversine 공식
위치 소스: 브라우저 Geolocation API (GPS)
```

### 1-2. 구조적 문제 분석 (2026-03-21 검토)

| 문제 | 내용 | 심각도 |
|------|------|--------|
| Grand/Premium 위치 무관 최상단 | GeoTargeting 도입 취지 반감 | 중간 |
| 좌표 미입력 업체 처리 | 서울 중심 배치 → 역차별 우려 (단, 공고등록 시 좌표필수이므로 실제 문제 없음) | 낮음 |
| 위치 거부 사용자 처리 | 정적 모드 = 구식 경쟁사와 동일 | 높음 |

### 1-3. 확정된 개선 방향

**정렬 우선순위 변경:**
```
1순위: 내 지역(시/도) Grand/Premium
2순위: 내 지역 나머지 등급 (거리 가까운 순)
3순위: 타지역 Grand/Premium (별도 섹션 또는 하단)
4순위: 타지역 나머지 등급
```

**"내 지역" 기준:**
- 시/도 단위 (서울, 경기도, 부산 등)
- 정확한 좌표가 아닌 시/도명으로 매칭
- 구직자 프라이버시 보호 (GPS 좌표 서버 미전송)

**좌표 미입력 업체:**
- 실제 문제 없음 — 공고 등록 시 사업자 정보 + 좌표 필수 입력
- 추가 처리 불필요

### 1-4. IP Fallback 전략 (확정 채택)

위치 권한 거부 구직자 대상:
```
Geolocation 거부 → ipapi.co 또는 ip-api.com API 호출
→ IP 기반 시/도 추정
→ 해당 시/도 기준 정렬 적용
→ 완전 실패 시: 전국 랜덤 정렬 (기존 방식)
```

구현 위치: `src/hooks/useLocation.ts`

### 1-5. 구직자 Stealth 안전장치 (확정)

유흥업종 특성상 1순위 거부감 = **주변인에게 유흥알바 사실이 노출되는 것**

| 노출 경로 | 위험도 | 처리 방법 |
|----------|--------|----------|
| 푸시 알림 잠금화면 | 최고 | 내용 없이 "새 알림이 있습니다"만 표시 |
| 위치 기반 알림 (백그라운드) | 최고 | 구직자에게 절대 미적용 |
| 브라우저 최근 방문 기록 | 높음 | 시크릿 모드 안내 |
| SNS 로그인 연동 | 높음 | **SNS 로그인 미제공** (자체 로그인만) |
| 앱 아이콘 노출 | 중간 | PWA 아이콘 중립 네이밍 가능 |

**핵심 원칙:**
> "코코알바는 구직자가 직접 앱을 열 때만 작동합니다. 백그라운드 추적, 노출성 알림 없습니다."

### 1-6. 위치 데이터 처리 원칙

## PART 2. SOS 긴급구인 알림 시스템

### 2-1. 개요

업체회원이 "지금 당장 일이 많다"는 긴급 상황을 구직자들에게 실시간 알림으로 발송하는 기능.

**핵심 가치:**
- 업체: 공고와 별개로 실시간 긴급 인력 모집
- 구직자: 일이 없는 날 다른 업소의 일감 확인 가능
- 코코알바: 포인트 소비 유발 → 수익화

### 2-2. 네이밍 & 브랜딩

```
기능명: SOS 긴급구인 알림 (SOS Alert)
아이콘: 🆘 또는 ⚡
색상: 빨간색 계열 (#ef4444)
슬로건: "지금 당장, 바로 출근 가능한 분?"
```

### 2-3. 업체회원 발송 플로우

```
1. 업체 마이페이지 → "SOS 긴급구인" 탭
2. 발송 지역 선택 (지역 필터링)
   - 옵션A: 업체 소재지 자동 설정
   - 옵션B: 직접 지역 선택 (타 지역 구직자도 포함 가능)
   - 이유: 경기권/지방은 타지역 출근자 비율이 높음
3. 현재 수신 가능 구직자 수 표시 (실시간)
   → "이 지역 알림 수신 동의 구직자: N명"
4. 메시지 작성 (최대 50자)
   → 예: "지금 일 미친듯이 많음! 바로 출근 가능한 분 연락주세요!"
5. 포인트 차감 확인 → [SOS 발송] 버튼
6. 발송 완료 → 알림 이력 저장
```

### 2-4. 지역 필터링 전략

경기권/지방 특성 반영:
```
발송 지역 선택 옵션:
[ ] 업체 소재 구/군 (기본)
[ ] 업체 소재 시/도 전체
[ ] 전국 (수도권 집중 기간)
[ ] 직접 선택 (다중 지역 선택)
```

→ 지역 넓을수록 더 많은 수신자 → 더 높은 포인트 차감

### 2-5. 포인트 차감 구조 (수신 인원 기반)

| 예상 수신 인원 | 차감 포인트 | 비고 |
|--------------|------------|------|
| ~10명 | 200P | 소규모 지역 |
| ~30명 | 400P | 중규모 |
| ~50명 | 600P | 대규모 |
| 50명 이상 | 800P | 광역 |

> **가격 정책은 추후 조정 가능. 기술 구현 먼저.**

### 2-6. 구직자 수신 플로우

```
1. 코코알바 최초 방문/로그인 시
   → "SOS 긴급구인 알림 받기" 동의 요청
   → 사전 설명 모달 표시:
      "업소에서 긴급 구인 시 알림을 드립니다.
       정확한 위치 및 개인정보는 전달되지 않습니다."

2. 동의 시 Web Push 구독 등록 (Supabase push_subscriptions 저장)

3. 알림 수신:
   → 잠금화면: "새 알림이 있습니다" (내용 없음 — Stealth)
   → 앱 오픈: "[업소명] 지금 일 많음! 바로 출근 연락주세요! 010-xxxx"

4. 알림 클릭 → 해당 업소 공고 상세 페이지로 이동
```

### 2-7. Stealth 알림 정책 (확정)

유흥업종 구직자 보호:
```
잠금화면 표시: "새 알림이 있습니다" ← 코코알바 언급 없음
알림음: 시스템 기본음 (튀는 소리 없음)
발신자명: "알림" (앱 이름 최소화)
내용 확인: 앱을 직접 열어야만 가능
```

### 2-8. 신고 기능 (확정 설계)

**원칙: 즉시 신고 버튼 없음 — 실제 출근 후 확인된 허위만 신고 가능**

이유: 귀찮아서 누르는 허위 신고 방지

```
신고 경로:
1. 해당 업소 공고 상세 페이지 → [허위 SOS 신고]
2. 마이페이지 → 1:1 문의 → "SOS 허위 신고"

신고 내용:
- "출근했는데 일이 없었다"
- "연락이 되지 않는다"
- "다른 업소였다" 등

어드민 처리:
- 신고 N회 누적 업체 → 경고
- 포인트 환불 거부
- 계정 제재
```

### 2-9. 카카오 알림톡 미적용 이유

```
카카오 비즈니스 채널 심사 → 유흥/성인 업종 자동 반려
문자(SMS) → 080 수신거부 의무 + 발신번호 등록 복잡 + 비용
→ Web Push가 현재 가장 현실적이고 무료
```

### 2-10. Web Push 기술 구조

```
[업체 SOS 발송]
      ↓
[Supabase: sos_alerts 테이블 INSERT]
      ↓
[Next.js API: /api/sos/send]
      ↓
[web-push 라이브러리]
      ↓
[구직자 브라우저 Push 서버 (Google FCM / Apple APNs)]
      ↓
[구직자 폰 알림 수신]
      ↓
[Service Worker (public/sw.js): 알림 표시 처리]
```

**플랫폼별 지원 현황:**
| 플랫폼 | 조건 | 비고 |
|--------|------|------|
| 안드로이드 크롬 | 설치 불필요 | 가장 넓은 커버리지 |
| PC 크롬/엣지 | 항상 가능 | |
| 아이폰 | iOS 16.4+ + PWA 홈화면 추가 | 2023년부터 지원 |
| 아이폰 Safari (비PWA) | ❌ 미지원 | |

**VAPID 키:**
- 서버에서 생성 (web-push 라이브러리)
- .env.local에 VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY 저장

## PART 3. 포인트 시스템 규칙

### 3-1. 포인트 사용처 (확정)

| 사용처 | 차감량 | 대상 |
|--------|--------|------|
| 이력서 점프 | -500P | 구직자 |
| 공고 점프 (추후) | -500P | 업체회원 |
| SOS 긴급구인 알림 | -200~800P | 업체회원 |
| 쿠폰 교환 | -5000P | 공통 |

### 3-2. 포인트 적립처 (확정)

| 적립처 | 적립량 | 대상 |
|--------|--------|------|
| 회원가입 | +1,000P | 공통 |
| 이력서 등록 | +5,000P | 구직자 |
| 커뮤니티 게시글 | +200P | 공통 |
| 커뮤니티 댓글 | +50P | 공통 |
| 어드민 수동 지급 | 자유 | 공통 |
| 포인트 충전 (결제) | 결제금액 비례 | 추후 구현 |

### 3-3. DB 구조

```sql
-- profiles 테이블 (기존)
profiles.points INT DEFAULT 0

-- point_logs 테이블 (기존)
point_logs: user_id, amount, reason, note, created_at

-- 추가 필요 테이블
sos_alerts:
  id UUID PRIMARY KEY
  shop_id UUID REFERENCES profiles(id)
  shop_name TEXT
  message TEXT (최대 50자)
  target_regions TEXT[] (발송 대상 지역 배열)
  point_deducted INT
  recipient_count INT
  sent_at TIMESTAMPTZ DEFAULT NOW()

push_subscriptions:
  id UUID PRIMARY KEY
  user_id UUID REFERENCES profiles(id)
  subscription JSONB (Web Push 구독 정보)
  regions TEXT[] (구직자 수신 희망 지역)
  created_at TIMESTAMPTZ DEFAULT NOW()
  updated_at TIMESTAMPTZ DEFAULT NOW()
```
