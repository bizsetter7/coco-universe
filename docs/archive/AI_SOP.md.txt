## 🔄 P2/P4 브랜드 전환(Switching) 기획 및 운영 시나리오
PG 심사 대응 및 본 서비스 전환을 위해 **단일 코드베이스에서 환경 변수 기반으로 즉시 UI/UX를 스위칭**하는 아키텍처를 강제한다.
- **P2 스위치 (`NEXT_PUBLIC_SERVICE_PHASE`):**
  - `PRE_RELEASE`: NICE 심사용 B2B 기업형 인재 솔루션 위장 랜딩페이지 및 메타데이터 노출
  - `PRODUCTION`: 유흥/고수익 알바 코코알바 본체 오픈 (알바 리스트 정상 표출)
- **금지어 및 코드 정화(Sanitization):** `isFake`, `auditMode` 등 의심되는 변수명 사용을 엄격히 금지하며, 심사 모드 시 백엔드 API 콜이 브라우저 Network 탭에 누출되지 않도록 원천 차단한다. 상세 내용은 P2 프로젝트 내 `docs/legal/P2_스위칭_사니타이제이션_기획서.md` 참조.

## 🛠️ 절대 운영 수칙
1. **기록 우선:** 모든 전략 변경, 코드 수정 사유, 목표 달성 현황은 즉시 이 파일(`AI_SOP.md`)에 기록한다.
2. **품질 검증:** 모든 작업 전후에 `Testsprite` 전수 검사를 실행한다. (특히 P3 지역별 URL 확인 필수)
3. **정보 공유:** 안티그래비티와 클로드 코드는 `Stitch MCP`를 통해 작업 로그를 실시간 동기화한다.
4. **표준 준수:** UTF-8 인코딩, Apple 1.1.4 가이드라인 선제 검토, 세련된 비즈니스 톤 유지.
5. **클로드 코드 협업 가이드 (인증 로직 보호):** `NTS API(api/nts/verify)` 및 통합 인증 모듈 관련해, **반드시 '사업자 인증 성공 -> 본인 인증 노출'** 시나리오를 정밀하게 검수하고 이 기획 의도가 어긋나지 않도록 연동한다.
6. **환경 변수 통제 원칙:** P2 및 P4의 스위칭 로직(예: `NEXT_PUBLIC_SERVICE_PHASE`) 조작 시, Vercel 환경 변수 업데이트 후 빌드 배포 단계를 엄격히 준수한다. (라이브 상태에서의 Hot-swap 에러 방지)
7. **[DB 무결성 및 구조 맵핑 원칙] (CRITICAL):** Supabase DB 상태 변경 로직 작성 시, 스키마에 존재하지 않는 컬럼(예: `pay_status`) 업데이트 시도 시 `PGRST204` 내부오류가 발생하므로, UI 참조 상태와 DB 스키마 객체는 엄격히 분리한다.
8. **[비동기 외부 SDK 통제 원칙] (CRITICAL):** 카카오맵 등 외부 SDK 로드 시 `script` 존재만으로 Promise를 resolve하지 말고, 내부 객체(`window.kakao.maps`) 초기화 여부를 `setInterval` 등으로 지연 확인하는 방어 코드를 필수 구성한다.


## ⚙️ 5단계 자동화 워크플로우 (The Perfect Process)
모든 에이전트는 작업 시 다음 단계를 '자동'으로 수행한다:
1. **[계획] Antigravity**: 비즈니스 목표 분석 및 구조 설계. AI_SOP.md에 '이유'와 '목표' 기록.
2. **[검증] Claude Code**: 설계된 구조의 논리적 오류 및 보안 취약점 사전 검토. (계획 검증)
3. **[실행] Antigravity (Composer)**: 검증된 계획을 바탕으로 실제 코드 구현 및 적용.
4. **[검증] Claude Code**: 구현된 코드의 작동 여부 및 인코딩(UTF-8) 등 실무 규격 검증. (코드 검증)
5. **[완결] TestSprite & Stitch MCP**: 작업 완료 후 
Test: UI 레이아웃(특히 모바일 1열 컴팩트 뷰), 모바일 호환성, 토글 버튼 기능 전수 조사.
Record: 작업 결과 및 패턴을 AI_SOP.md에 업데이트하고 스티치를 통해 에이전트 간 맥락 동기화.

## 🛡️ 본인인증 보안 표준 SOP (MANDATORY 필수 검수 체크리스트)
다날 본인인증 및 시스템 보안 적용 시 아래 5대 원칙을 **모든 프로젝트(P2, P4)** 배포 전 필수 검수 항목으로 삼는다. (미통과 시 배포 불허)

1. **데이터 무결성 검증 必:** 서버-to-서버 통신 시 사용자 정보(이름, 생년월일 등) 변조 방지 로직 적용.
2. **노출 방지 必:** 웹 소스코드 내 API 키, 비밀키 및 중요 개인정보 평문 노출 절대 금지.
3. **인증 프로세스 검증 必:** 인증 성공 페이지 URL에 대한 직접 접근 및 인증 결과 재사용(Authentication Bypass) 차단.
4. **강력한 암호화 必:** 모든 통신 구간(가맹점-다날-이동통신사)은 TLS 1.2 이상 보안 프로토콜 및 표준 암호화 알고리즘 적용 필수.
5. **마스킹 처리 必:** 사용자 확인 용도로 노출되는 주민등록번호 앞자리, 뒷자리 첫 번째 숫자 외 모두 마스킹 처리.
